## Основные проблемные зоны

1. **DWH-монолит на MS SQL Server 2008**  
   - в хранилище сосредоточено слишком много логики, связей и зависимостей, при этом платформа устарела.  
   - *Последствия:* расчёты занимают часы, растёт вероятность отказов и рисков EOL, доработки становятся дорогими, а вывод изменений на рынок замедляется.

2. **Глубокая кастомизация BI над DWH**  
   - часть бизнес-правил оказывается внутри отчётного слоя.  
   - *Последствия:* метрики расходятся между отчётами, появляется дублирование, требуются ручные корректировки, сопровождение усложняется.

3. **Модель доступа не выдерживает требований масштаба и комплаенса**  
   - клинические и аналитические данные пересекаются, а маскирование реализовано отдельными точечными решениями.  
   - *Последствия:* повышаются комплаенс-риски, аналитические задачи выполняются медленнее.

4. **Устаревшая интеграционная шина Camel становится единой точкой отказа**  
   - один механизм обслуживает разные типы сценариев, из-за чего систему сложно развивать.  
   - *Последствия:* копится очередь изменений, увеличиваются задержки, при росте нагрузки возможна деградация.

5. **Нет ясных доменных границ и закреплённой ответственности за данные**  
   - данные собираются в DWH, владельцы наборов не определены, согласования занимают много времени.  
   - *Последствия:* развитие упирается в организационные и технические узкие места, качество данных трудно контролировать.

6. **Увеличивается число партнёрских интеграций: фармацевтика и оборудование**  
   - телеметрия и B2B-сценарии создают дополнительный поток данных и операций.  
   - *Последствия:* без потоковой обработки платформа рискует не выдержать нагрузку.

7. **Высокая стоимость владения и зависимость от вендоров**  
   - прежние технологические решения повышают расходы и ограничивают выбор альтернатив.  
   - *Последствия:* масштабирование усложняется, а миграция требует значительных усилий.

## Приоритизация (MoSCoW)

**Must:**
- Построить платформу данных и включить стриминг/CDC для ключевых областей: финтеха, телеметрии оборудования и основных операционных БД.
- Запустить каталог данных и закрепить процессы доменного владения данными.
- Ввести IAM, политики доступа и маскирование: отделить PHI/ПДн от аналитических контуров и автоматизировать обезличивание.
- Создать портал витрины данных с поиском, карточками датасетов, заявками на доступ и публикацией отчётов.

**Should:**
- Снизить зависимость от Camel: перенести критичные интеграции на API Gateway и Kafka.
- Постепенно разгрузить легаси DWH: вынести вычисления в ELT, а DWH оставить как исторический источник.

**Could:**
- Перевести финансовую отчётность на новую архитектуру и заменить устаревшие отчёты.
- Добавить каталогизацию нефункциональных артефактов, включая API-контракты и SLA партнёров.

**Won’t:**
- Полностью выводить из эксплуатации PowerBuilder UI с переносом всех операционных сценариев.
- Переносить абсолютно все трансформации из DWH в рамках текущего этапа.
